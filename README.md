# Happy 3rd Year, My Love

A scroll-driven anniversary site: a pink sky that changes mood as you scroll, with framed photos (Memories) floating past and a 3D couple (the Flyers) trailing a pink ribbon and pink-and-orange Stardust along a path of climbs, dives, turns and one loop. See `.scratch/anniversary-site/spec.md` for the full plan and `GLOSSARY.md` for the terms.

## Run it

```bash
npm install
npm run dev        # http://localhost:3000, with hot reload
npm run build      # static export into out/
npm start          # serves out/ locally (any static server works)
```

`npm run build` writes a plain static site to `out/`. To put it online, drag the `out/` folder onto Netlify (or any static host). No server is needed. Step-by-step instructions, the day-of checklist and the list of known issues are in `DEPLOY.md`.

## Check a moment without scrolling

- `?p=0.4` opens the page at 40% of the scroll. Useful values: `0` dawn, `0.35` bright pink day, `0.7` sunset, `1` deep rose with stars (the Letter's last line).
- `?debug` shows live progress, frames per second (the number to watch when scrolling on a real phone), how many ScrollTriggers and ticker callbacks exist (it should always say 1 and 1), and how many screens long the story is and how many minutes a relaxed pass takes.
- Combine them: `/?p=0.7&debug`.
- `?p=`, `?debug` and `?open` skip the Unlock question, so you can check any moment. Without one of them the gate comes first (once answered, the tab remembers it until it is closed).


## Change the photos, Captions and Month labels

Everything lives in `content/memories.ts`. Left/right placement follows the order automatically.

There is one picture for every Month: **Year 1, Year 2 and Year 3 hold exactly 12 Memories each** (36 in all, in order, Month 1 is `DAY_ONE`'s own month), and **How we met holds 3**. A test fails if a Year does not have 12.

1. Copy photos into `public/photos/`.
2. `npm run resize-photos` scales them so the longest edge is about 1600 px (phone-friendly). It only touches jpg, jpeg, png and webp.
3. Point each Memory at its file. In a Year it is just the photo, e.g. `{ src: "/photos/us-at-the-beach.jpg" }`; the handwritten line under it is its Month label ("August 2024"), worked out from `DAY_ONE`, so you never type it. In How we met each Memory also has your own `caption`: `{ src: "/photos/01.jpg", caption: "…" }`. Set `ratio` (width / height) for landscape (`1.33`) or square (`1`) photos so nothing is cropped.
4. `alt` is optional on any Memory. It is what a screen reader says about the photo; the default is the Month label (or the Caption in How we met).

The Month labels are written in the language of `DATE_LOCALE`. If `DAY_ONE` falls on the 29th, 30th or 31st, a shorter month simply uses its last day.

The placeholder photos (39 of them) are generated by `node scripts/make-placeholders.mjs` and can be deleted once real ones are in.

## Her story: the gate, Day 1, the Intro and the Letter

All in `content/memories.ts`. The values there now are placeholders until you write the real ones.

- `DAY_ONE` is the day you became a couple (`YYYY-MM-DD`). The Day counter starts at Day 1 on that day, the Year 1, 2 and 3 Chapters open on it and its next two anniversaries, and the Anniversary is three years after, so changing `DAY_ONE` changes every date and every number. With the placeholder `2024-02-14` the counter ends on Day 1,097 (it spans a leap day). How we met sits before Day 1 and keeps its own date; the counter is hidden there. If you move `DAY_ONE` to or before that date, a test fails to tell you to move the How we met date back before it.
- `GATE` is the Unlock question: `question`, the accepted `answers` (case, spaces, punctuation and accents are ignored, so list a few real spellings, not typos), and the kind `wrongMessages` shown one after another. Keep the answer out of the question and the messages (a test checks). It is a soft lock for a surprise, not security: anyone who reads the page's code can see the answers.
- `INTRO` is the title screen after the gate opens.
- `LETTER` is the `greeting`, the `body` (a list of paragraphs) and the `closing` line. The body comes in line by line; a longer Letter scrolls for longer and slides up inside the card so the newest line is always visible. The script font draws Latin letters, digits and common punctuation and accents.

How long the story is, in screens, and how many seconds a screen takes at a relaxed pace, are `SCREENS` and `RELAXED_SECONDS_PER_SCREEN` at the top of `lib/timeline.ts`. Add or remove Memories and the length follows.

## The Song and the Sound button

`SITE.song` in `content/memories.ts` is the path of one MP3 inside `public/` (for example `"/audio/our-song.mp3"`, about 3 to 4 MB). With it set, a round Sound button sits in the bottom-right corner; one tap plays the Song (on a loop), the next pauses it. Nothing plays, and nothing is downloaded, until she taps. Leave `SITE.song` as `""` and there is no button: the site works silently. If the path is wrong or the file will not load, the button disappears at her first tap (that is the first moment anything is fetched), so tap it once on the live site to check. The music pauses when she leaves the page and picks up again when she comes back (unless she had paused it herself), and the button follows the music if the phone pauses it by itself (a call, Siri, unplugged headphones).

## When 3D is not available

With the device's Reduce Motion setting on, or no WebGL, the page shows the plain stacked list instead: the Intro, then every Memory in its pink frame with its Month label (or its Caption in How we met), each Chapter opened by its title, date and Day number, the Anniversary's own day number, and the Letter at the end. Nothing flies. If the browser takes the 3D layer away (an iPhone does that when she switches apps) the page redraws it as soon as the browser gives it back, builds a fresh one if it never does, and falls back to the plain list if that keeps failing.

If the link is opened inside another app's own browser (Instagram, Facebook, TikTok and similar), a dismissible "Open in Safari for the best experience" note shows at the top.

The page carries `noindex`, and `public/_headers` sends the same instruction for every file when the site is on Netlify.

## The Flyers (the 3D couple)

By default the Flyers are a simple low-poly couple built in code (`lib/flyers.ts`), in flat colours with a pink rim light. To use your own model, drop a binary glTF at `public/models/couple.glb`: no code change is needed.

- Budget: at most 2 MB and 30,000 triangles. Draco or Meshopt compression is not supported.
- Face the model along +x (to the right) with +y up. It is scaled to fit and centred automatically, and it keeps its own colours (a soft pink rim is added to each standard material).
- A missing, oversized, over-budget or broken file quietly falls back to the built-in couple.

The route they fly is the list of turns at the top of `lib/route.ts` (`TURNS` for wide screens, `PORTRAIT_TURNS` for phones held upright). Edit those to change the flight.

## Notes

- The handwriting is Pinyon Script (SIL Open Font License; licence in `lib/fonts/Pinyon-Script-OFL.txt`), stored in `lib/fonts/pinyon.ts` as the real letter outlines plus a derived pen path for each letter, so text can write itself on while always showing the genuine Pinyon letters. Nothing loads from a CDN or font service. It covers Latin letters, digits and common punctuation and accents only; to change the font or add characters, run `npm run make-script-font -- path/to/Font.ttf` (it regenerates the file and reports any letter its pen path does not fully cover).
- Dependency versions are pinned exactly (see `.npmrc`).
